# easy_plan — 교수학습 및 평가 운영계획서 생성기

고등학교 교사가 **교수학습 및 평가 운영계획서**를 작성하고 완성된 한글 문서(.hwpx)를
내려받는 웹앱. 20쪽 가까운 계획서에 표가 30개 넘고 같은 값이 문서 여러 곳에 반복되는데,
**값을 한 번만 입력받아 문서 전체를 렌더링**한다.

입력 경로는 두 가지이고 데이터 모델과 출력은 완전히 공유한다. 두 앱이 아니라 입력 화면만 두 벌이다.

- **심화** — 교사가 직접 채운다 (6단계)
- **간단** — 6가지만 입력하면 나머지를 채운다

## 설계 원칙

1. **값만 저장한다.** 완성된 문장을 저장하지 않는다
2. **같은 값은 한 곳에만.** 나머지는 전부 참조
3. **문단에 번호를 넣지 않는다.** 가·나·다는 출력 시점에 부여
4. **파생값은 저장하지 않는다.** 필요할 때 계산 → [`src/lib/derive.ts`](src/lib/derive.ts)
5. **AI는 문장만 쓴다. 숫자는 코드가 정한다** → [`src/lib/autofill.ts`](src/lib/autofill.ts)

## 성취기준 데이터

`data/고등학교_성취기준_2022.xlsx`의 `전체_성취기준` 시트를 읽는다. 3,261행.
2015 파일은 척도가 3단계라 Ⅺ 표(A~E)와 구조가 맞지 않아 쓰지 않는다.

```bash
npx tsx scripts/inspect-standards.ts
```

```bash
npm run seed:subject -- "미적분Ⅰ"
```

파일에서 확인한 것 — 파서는 이걸 전제로 돈다:

- 열 이름은 `수준1(A/상)` `수준4(D)` 처럼 괄호가 붙는다. 접두로 찾는다
- `척도유형`은 `5단계(A~E)` 2790 · `LVL_4` 168 · `3단계(상~하)` 298 · 빈칸 5
- **`LVL_4`는 168행 모두 수준5까지 차 있다.** A~E로 취급한다
- `3단계(상~하)`는 수준4가 한 행도 없다. Ⅺ 표에서 D·E 행을 비운다
- `영역(단원)`은 90.9%만 채워져 있다 (결측: 국어·영어·제2외국어·한문)
- 여는 대괄호가 빠진 행이 5개 있다 (`12진로01-03] …`). 파서가 받아 준다
- `평가준거 성취기준` 열은 쓰지 않는다. 양식은 원문을 쓴다

## hwpx 생성

```bash
npm run template      # templates/reference.hwpx → templates/plan_blank.hwpx
```

```bash
npm run render:test   # 시드 데이터로 out/test-render.hwpx 생성
```

```bash
npm run verify:hwpx out/test-render.hwpx
```

구현은 [`src/lib/hwpx/doc.ts`](src/lib/hwpx/doc.ts) (조작) 와
[`src/lib/hwpx/render.ts`](src/lib/hwpx/render.ts) (값 → 표·문단).
`docs/hwpx_참조구현.py`의 파이썬 구현을 포팅한 것이고, 실패를 겪고 알아낸 여섯 가지를 그대로 지킨다.

1. **mimetype은 zip 첫 항목, 무압축(STORED)** — 폴더째 다시 압축하면 깨진다
2. **문자열 치환 금지** — 한글은 한 줄을 여러 `<hp:t>` 조각으로 쪼갠다. 문단 단위로 다룬다
3. **빈 셀에는 `<hp:t>`가 없다** — 만들어 넣지 않으면 조용히 비어 나온다
4. **여러 줄 셀은 `<hp:p>`를 깊은 복사**해서 서식을 유지한다
5. **행 복제 후 `cellAddr/rowAddr` 재부여 + `tbl/rowCnt` 갱신** — 빠뜨리면 표가 깨진다
6. **글자를 바꾼 문단의 `<hp:linesegarray>`를 지운다** — 줄바꿈 캐시라서 그냥 두면 자간이 뭉개진다

렌더러는 표를 번호가 아니라 **머리행 글자(서명)** 로 찾는다. 양식이 조금 바뀌어도 버틴다.
반복되는 표(수행평가 세부기준 · Ⅺ 성취수준)는 템플릿에 한 벌만 두고 문단째 복제한다.

> **한글에서 직접 열어 확인할 것.** zip 무결성과 XML 파싱만으로는 부족하다.
> 표 테두리와 셀 높이가 깨지지 않는지가 진짜 기준이다.

### 아직 남은 것

- **Ⅳ 평가 계획 표의 기하**는 템플릿 것을 그대로 쓴다. 정기시험 2회 × (선택형·서술형) +
  수행평가 N개 기준이다. 칸 수가 안 맞으면 앞에서부터 채우고 경고를 낸다
  (응답 헤더 `X-Render-Warnings`, 내려받기 화면에 표시)
- 2학기 학사일정 (주차 수·양식 차이 미확정)

## 검증

로직 15개는 전부 결정적이고, 하나라도 걸리면 내려받기를 막는다 →
[`src/lib/validate.ts`](src/lib/validate.ts). AI 검토는 표시만 하고 막지 않는다.

10번(모든 성취기준이 어느 주차엔가 배정됨)이 가장 중요하다. 누락되면 진도표뿐 아니라
시험 범위와 Ⅺ 표까지 전부 어긋난다. 미배정 목록을 항상 노출한다.

**간단 작성의 결과는 검증을 처음부터 통과한 상태로 나온다.** 실시 주차를 고를 때
규칙 11·14·15를 미리 피하고, 기본점수는 만점의 30%, 루브릭 배점 합은 영역 만점에 맞춘다.

## AI

`/api/ai`가 OpenRouter를 프록시한다. **키는 서버에만 둔다.** 허용한 작업만 받는다 —
단원 매칭 초안 · 주차별 수업 방법 · 수행 활동 과정 · 루브릭 기준 서술 · Ⅰ·Ⅱ 서술 · 정합성 검토.

숫자는 AI가 정하지 않는다. 반영 비율(수행평가 개수로 균등 분배) · 영역 만점 · 기본점수 ·
배점 · 서술논술 비율은 전부 코드가 계산한다.

`OPENROUTER_API_KEY`가 없으면 화면의 AI 검토는 결정적 휴리스틱으로 돈다
(금지 명칭 · 루브릭 배점 간 구분 · 성취기준 중복 사용 · 안내 주 준비 기간).

## 확인이 필요한 값

| 항목 | 지금 구현 | 확인할 것 |
|---|---|---|
| 월 기준 주차 | 시작일이 속한 달 기준 (기본) / 1일 낀 주 = 1주 (선택) | 담당자가 양식 예시 방식을 요구하는지. 같은 주라도 라벨이 한 주씩 밀린다 |
| 예정시간 | `round(학점 × 수업일 / 5)` | 필드정의서는 `학점 × 수업일`이라 단위가 안 맞고, 미적분Ⅰ 예시는 4일 주에도 학점 그대로를 적었다 |
| 루브릭 배점 합 | 영역 만점과 같아야 함 (규칙 7) | 기본점수를 뺀 값이어야 하는지. 지금은 규칙 문구 그대로 |
| 기본점수 하한 | 만점의 20% (규칙 4) | 디자인 시안은 15%를 '검증 통과'로 표시한다. 규칙을 따랐다 |
| 안내 주 충돌 | 가까운 주로 앞뒤 모두 탐색 | 앞으로 당길지 뒤로 밀지 |
