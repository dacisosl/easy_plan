# 첫 화면 다시 짜기 — 계획

2026-07-29 · 문제: **심심하다. 눈에 안 들어온다. 그냥 나갈 것 같다.**

---

## 0. 지금 뭐가 문제인가

```
        선생님, 편집은 제가 할게요.        ← 38px, 화면의 1/12
   평가 기획만 해주세요 — 20쪽 …          ← 16px 회색
        ┌──────────────────────┐
        │ 과목  [🔍 검색     ] │          ← 흰 상자, 흰 배경
        └──────────────────────┘
```

세 가지가 겹쳤다.

1. **크기 대비가 없다.** 38px는 "제목치고 좀 큰 글씨"지 헤드라인이 아니다.
   찾아본 자료들이 공통으로 말하는 건 *"처음 보면 불편할 만큼 커야 한다"* 였다.
2. **화면이 전부 흰색이다.** 헤드라인·부제·검색 상자·배경이 전부 흰 바탕이라
   눈이 어디에 멈춰야 할지 신호가 없다.
3. **왜 써야 하는지가 없다.** 약속(편집은 제가)만 있고 **증거가 없다.**
   교사는 "또 하나의 안 되는 도구"를 수없이 겪었다. 숫자가 있어야 믿는다.

---

## 1. 레퍼런스에서 가져올 것

찾아본 것 중 이 도구에 맞는 것만 추린다.

| 출처 | 가져올 것 | 버릴 것 |
|---|---|---|
| Figma 2026 트렌드 (bold typography) | **헤드라인을 불편할 만큼 크게.** 여백이 클수록 큰 글씨가 더 세게 꽂힌다 | 가변폰트 애니메이션 — 공공문서 도구엔 과하다 |
| SaaSFrame ① 스토리형 히어로 | **before → after 구조.** 문제를 먼저 보이고 해결을 붙인다 | 3D 일러스트 |
| SaaSFrame ⑥ 스플릿 레이아웃 | 문제/해결 대비 | 50:50 분할 — 할 일이 하나뿐인 화면이라 안 맞는다 |
| SaaSFrame ⑦ 진짜 화면 보여주기 | **추상 그림 대신 실제 산출물.** 우리는 hwpx 문서가 결과물이다 | 스톡 이미지 |
| Perfect Afternoon 히어로 원칙 | **CTA는 하나.** 히어로가 화면의 60~100%를 차지 · 5초 안에 이해 | — |
| 대비 원칙 | 표현적인 큰 글씨 + 가장 담백한 본문 | 세리프 헤드라인 — 학교 문서 톤과 안 맞는다 |

**핵심 한 줄**: 큰 글씨 + 넓은 여백 + 하나의 CTA + **숫자로 된 증거**.

---

## 2. 이 도구만의 사정

일반 SaaS 랜딩과 다른 점이 셋 있다.

- **로그인이 없다.** 첫 화면이 곧 작업 화면이다. "둘러보기"가 없고 바로 시작한다
  → CTA가 버튼이 아니라 **과목 검색창** 자체다. 여기에 힘을 실어야 한다.
- **사용자가 이미 지쳐 있다.** 밤새 한글 표를 만지다 온 사람이다.
  자극적인 마케팅 톤은 오히려 불신을 산다. **담백하되 크게.**
- **결과물이 눈에 보인다.** 20쪽짜리 hwpx. 이게 가장 강한 증거다.

## 3. 새 구성

```
┌─────────────────────────────────────────────────┐
│                                                  │
│   [연한 배경 웨이시 · 격자]                        │
│                                                  │
│   ██ 20쪽 · 표 30개 · 문장 200줄                  │  ← 문제 (작게, 회색)
│                                                  │
│   선생님,                                        │  ← 56~72px
│   편집은 제가 합니다.                             │  ← 청남색 강조
│                                                  │
│   과목만 고르면 나머지는 채워집니다.                │  ← 17px
│                                                  │
│   ┌───────────────────────────────┐             │
│   │ 🔍  과목명을 입력하세요          │  [시작 →]  │  ← 56px 높이, 그림자
│   └───────────────────────────────┘             │
│                                                  │
│   231개 과목 · 성취기준 3,261개 · 한글 파일 그대로  │  ← 증거 칩
│                                                  │
└─────────────────────────────────────────────────┘
```

### 문구 — 선생님 안대로

`선생님, 편집은 제가 합니다.` 로 간다. 제가 만든 "할게요"보다 낫다.
**단정형이라 약속처럼 들린다.** "할게요"는 부탁받은 사람의 말투다.

- 윗줄 `선생님,` 은 작게 (호명)
- 아랫줄 `편집은 제가 합니다.` 를 크게, `편집`에 색
- 느낌표는 뺀다 — 큰 글씨가 이미 강조라 겹치면 소리만 커진다

### 위쪽 작은 줄 = 문제 제시

`20쪽 · 표 30개 · 문장 200줄` — 교사가 매 학기 실제로 만지는 분량이다.
헤드라인 앞에 두면 **"그래서 그걸 내가 한다"**로 읽힌다. before → after 구조.

### 아래 증거 칩

숫자 셋. 지어내지 않고 **코드에서 실제로 세서** 넣는다.

- 과목 수 — `/api/subjects` 실제 개수
- 성취기준 수 — 2022 개정 파일에 든 실제 행 수
- `한글 파일 그대로` — 별도 뷰어 없이 hwpx로 나온다는 뜻

### 배경

흰 바탕만으로는 헤드라인이 뜨지 않는다. **아주 옅은 청색 웨이시 + 격자**를
히어로 뒤에만 깐다. 색을 넣는 게 아니라 *바닥을 만들어* 글씨가 그 위에 서게 한다.

---

## 4. 지키는 것

- 색은 지금 팔레트 그대로 — 파랑 하나. 새 색을 들이지 않는다
- 애니메이션은 진입 페이드만. 스크롤 효과·패럴랙스 없음
- CTA 하나. 검색창 = 시작
- 과목을 고르면 지금처럼 부드럽게 작성 화면으로 넘어간다

## 5. 안 하는 것

- 세리프 헤드라인 (학교 문서 톤과 충돌)
- 3D·일러스트·스톡 이미지
- 스크롤해야 보이는 추가 섹션 — 로그인 없는 도구라 스크롤할 이유가 없다
- 느낌표·이모지 남발

## 6. 검증

- 헤드라인이 두 줄로 유지되는지 (세 줄로 깨지면 실패)
- 5초 안에 "무슨 도구인지" 읽히는지 — 선생님 눈으로
