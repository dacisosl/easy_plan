## 만들 것

고등학교 교사가 **교수학습 및 평가 운영계획서**를 작성하고, 완성된 한글 문서(.hwpx)를
내려받는 웹앱.

교사는 매 학기 20쪽 가까운 계획서를 손으로 쓴다. 표가 30개 넘고 같은 값을 문서
여러 곳에 반복해서 적어야 해서 실수가 잦다. 이 앱은 **값을 한 번만 입력받아
문서 전체를 렌더링**한다.

입력 경로가 두 가지다.

- **심화** — 교사가 직접 채운다
- **간단** — 6가지만 입력하면 AI가 나머지를 채운다

데이터 모델과 출력은 완전히 공유한다. **두 앱이 아니라 입력 화면만 두 벌이다.**

## 기술 스택

- Next.js 15 (App Router) + TypeScript
- Tailwind CSS
- hwpx 처리: `jszip` + `@xmldom/xmldom`
- AI: OpenRouter. **반드시 서버 라우트에서만 호출.** 키를 클라이언트에 노출하지 말 것
- 저장: Prisma + SQLite로 시작

## 설계 원칙

1. **값만 저장한다.** 완성된 문장을 저장하지 않는다
2. **같은 값은 한 곳에만.** 나머지는 전부 참조
3. **문단에 번호를 넣지 않는다.** 가·나·다는 출력 시점에 부여
4. **파생값은 저장하지 않는다.** 필요할 때 계산
5. **AI는 문장만 쓴다. 숫자는 코드가 정한다**

## hwpx 생성 — 실험으로 확인한 것, 반드시 지킬 것

`hwpx_참조구현.py`에 동작하는 파이썬 구현이 있다. **먼저 읽고 TypeScript로 포팅하라.**
아래 여섯 가지는 실제로 실패를 겪고 알아낸 것이므로 하나도 빠뜨리지 말 것.

### ① mimetype은 첫 번째 항목, 무압축

hwpx는 zip이다. 그러나 `mimetype`(19바이트, 내용 `application/hwp+zip`)이
**압축 목록의 맨 앞**에 있어야 하고 **압축이 걸리면 안 된다**(STORED).
폴더를 통째로 다시 압축하면 이 조건이 깨져 한글이 열지 못할 수 있다.

```ts
const zip = new JSZip();
zip.file('mimetype', mimetypeBytes, { compression: 'STORE' });
for (const name of otherFiles) zip.file(name, data[name], { compression: 'DEFLATE' });
```

### ② 문자열 치환 금지

한글은 한 줄의 글자를 여러 `<hp:t>` 조각으로 쪼개 저장한다. 실제 예:

```
run 1 │ 2026학년도 ○학년 1학기 <
run 2 │  과목명 >
run 3 │ 교수학습 및 평가 운영계획
```

`< 과목명 >`을 문자열로 찾으면 **절대 안 걸린다.** XML을 파싱해서 문단(`<hp:p>`)
단위로 다뤄라. 문단의 모든 `<hp:t>`를 합쳐 판단하고, 새 글자는 첫 조각에만 넣고
나머지는 빈 문자열로 만든다.

### ③ 빈 칸에는 글자를 담을 자리가 없다

템플릿의 빈 셀은 이렇게 생겼다.

```xml
<hp:p ...><hp:run charPrIDRef="32" /><hp:linesegarray>...</hp:linesegarray></hp:p>
```

`<hp:t>`가 아예 없다. 여기에 글자를 쓰려면 `<hp:t>`를 만들어 `<hp:run>` 안
맨 앞에 넣어야 한다. **이걸 빠뜨리면 예시 글자가 있던 칸만 채워지고 나머지는
조용히 비어 나온다.** 오류도 안 난다.

### ④ 문단이 여러 개인 셀

한 셀에 여러 줄을 넣으려면 `<hp:subList>` 안의 `<hp:p>`를 복제한다.
첫 문단을 기준으로 deepcopy 한 뒤 텍스트만 갈아끼운다. 서식이 유지된다.

### ⑤ 행 복제 — rowAddr 재부여와 rowCnt 갱신이 필수

성취기준 표는 성취기준 하나당 5행(A~E)이다. 과목마다 개수가 달라서
템플릿(15행)으로는 모자란다. 성취기준 10개면 51행이 필요하다.

절차:

1. 머리행을 뺀 나머지에서 **5행 블록**을 템플릿으로 확보
2. 머리행 외 전부 제거
3. 필요한 개수만큼 블록을 deepcopy 해서 append
4. **모든 `<hp:tc>`의 `<hp:cellAddr rowAddr>`을 행 순서대로 다시 매긴다**
5. **`<hp:tbl rowCnt>`를 실제 행 수로 갱신한다**

4번과 5번을 빠뜨리면 한글에서 표가 깨진다.

### ⑥ 글자를 바꾼 문단은 줄바꿈 캐시를 지운다

각 문단에는 줄바꿈 위치가 미리 계산되어 저장돼 있다.

```xml
<hp:linesegarray>
  <hp:lineseg textpos="0" vertsize="800" horzsize="9744" ... />
</hp:linesegarray>
```

`horzsize`는 "이 문단은 폭 9744짜리 한 줄"이라는 뜻이다. 글자를 더 긴 것으로
바꾸고 이 캐시를 그대로 두면, 한글이 **새 글자를 옛날 한 줄에 욱여넣으면서
자간을 뭉갠다.** 글자가 겹쳐 보이고, 사용자가 엔터를 쳐야 풀린다.

**글자를 바꾼 문단의 `<hp:linesegarray>`를 통째로 제거하라.** 한글이 파일을 열 때
다시 계산한다. 손대지 않은 문단의 캐시는 남겨둔다.

```python
for lsa in list(p.findall(q('linesegarray'))):
    p.remove(lsa)
```

### 템플릿 준비

배포된 양식에서 예시 내용과 안내문을 걷어낸 **빈 템플릿**을 하나 만들어
`templates/`에 둔다. 자리표시자가 들어갈 칸은 **문단 하나에 조각 하나**만
남겨두면 치환이 단순해진다.

### 조건부 삭제와 번호 재부여

양식에는 "삭제 후 번호를 다시 매기라"는 지시가 다섯 군데 있다.

| 조건 | 처리 |
|---|---|
| 정기시험 없음 | Ⅲ-2-다 대체, Ⅷ-가 제거 |
| 1단위 과목 또는 수행평가 80% 이상 | Ⅲ-2-마 제거 |
| 등급 미산출 과목 | Ⅲ-2-사 제거 |
| 진로와 직업 | Ⅲ-1-나 제거, P/F 문구 추가 |
| 고정분할점수 | Ⅲ-2-나 제거 |
| 공통과목 아님 | Ⅺ 최소 성취수준 행 제거 |

그래서 Ⅲ·Ⅶ·Ⅷ·Ⅸ·Ⅹ의 문단은 **번호 없이** 저장하고 조건 태그만 붙인다.
출력 시점에 조건을 평가해 살아남은 문장에 가·나·다를 순서대로 부여한다.
문장 안에 `가.`를 하드코딩하면 반드시 깨진다.

## 성취기준 데이터

`고등학교_성취기준_2022.xlsx`의 `전체_성취기준` 시트를 읽는다.
2015 파일은 척도가 3단계라 양식(A~E)과 구조가 맞지 않으므로 쓰지 않는다.

열: 교과 · 과목 · 학년(군) · 영역(단원) · 성취기준 · 평가준거 성취기준 · 척도유형 · 수준1~5

파싱 규칙:

- `성취기준` 열은 `[코드]\n문장` 형태. 첫 줄이 코드, 나머지가 문장
- `평가준거 성취기준`은 쓰지 않는다. 양식은 원문을 쓴다
- `척도유형`의 `LVL_4`는 표기만 그럴 뿐 5칸이 다 차 있다. A~E로 취급
- `3단계(상~하)` 과목(28개)은 Ⅺ 표에서 D·E 행을 비운다
- `척도유형`으로 Ⅴ 성취도 기준표를 자동 판정한다
- `영역(단원)` 열이 진도표 단원명 윗줄과 Ⅺ 표 분할의 근거다 (91% 채워짐)

## 파생값 — 저장하지 말고 계산할 것

| 값 | 계산 |
|---|---|
| 예정시간 / 실시누계 | 주당 시수 기준, 시험 주는 축소, 누계 |
| 기간 표시 | 주차의 시작·종료일 포맷 |
| 월 기준 주차 | 아래 규칙 참고 |
| 영역 만점 | 반영 비율 × 100 |
| 서술·논술 합계 | (서술 배점 ÷ 시험 만점) × 시험 반영비율 의 총합 |
| 시험별 성취기준 범위 | 앵커 단원 → 단원 → 성취기준 코드 |
| 진도 배분 | 앵커 사이 단원을 주차에 분배 |
| 수행평가 안내 주 | 실시 주 − 2 |
| 배점 합 목록 | 최대합부터 최소합까지 급간만큼 |
| 동점자 처리 순서 | 2회 → 1회 → 수행1 → 수행2 |
| 가·나·다 번호 | 조건 통과 문장에 순서대로 |

### 월 기준 주차 규칙

**시작일이 속한 달로 귀속하고, 그 달에서 시작하는 주 중 몇 번째인지 센다.**

```
month = week.start.getMonth() + 1
n     = 같은 달에서 시작하는 주 중 이 주의 순번
label = `${month}월 ${n}주`
```

주차와 라벨이 1:1이라 역변환이 된다. 달을 걸친 주는 시작일 쪽 달에만 속한다.

## 검증 규칙

### 로직 (자동, 오류면 내려받기 차단)

1. 반영 비율 합 = 100%
2. 수행평가 한 영역 ≤ 35%
3. 서술·논술 합계 ≥ 30%
4. 기본점수 = 영역 만점의 20% 이상 ~ 40% 미만
5. 기본점수 > 1점
6. 영역 만점 = 반영 비율과 일치
7. 루브릭 배점 합 = 영역 만점
8. 수행평가별 성취기준 ≤ 6개
9. 성취기준 코드가 과목 목록에 실제 존재
10. **모든 성취기준이 어느 주차엔가 배정됨** — 미배정 목록을 반드시 노출
11. 수행평가가 2회 정기시험 이전에 완료
12. 수행평가명 20자 이내
13. 시험 범위 성취기준이 해당 시점까지 진도에 포함
14. 평가 시기가 특정 주에 몰리지 않음
15. 안내 주(실시−2주)가 시험 주·비수업 주와 겹치지 않음

10번이 가장 중요하다. 성취기준이 누락되면 진도표뿐 아니라 시험 범위와 Ⅺ 표까지
전부 어긋난다.

### AI (표시만, 차단하지 않음)

- 성취기준과 그 주 수업 내용의 정합성
- 평가 요소가 성취기준을 실제로 측정하는가
- 수행평가명이 금지 유형(주제탐구보고서·말하기·쓰기 등)에 해당하는가

### 인간 확인

포커스를 옮겨가며 항목마다 확인 버튼을 누르게 한다. 목록으로 돌아가지 않고
항목에서 항목으로 넘어간다.

## AI 사용 규칙

**AI가 정해도 되는 것 — 문장뿐이다.**

- 주차별 수업 방법 및 주안점
- 수행 활동 과정
- 루브릭 채점 기준 서술
- Ⅰ 교수학습 운영계획, Ⅱ 평가의 목적
- 단원 ↔ 성취기준 매칭 초안

**AI가 정하면 안 되는 것 — 전부 코드로 계산한다.**

- 반영 비율 (수행평가 개수로 균등 분배)
- 영역 만점 (비율 × 100)
- 기본점수 (만점의 30%)
- 배점 (평가 요소 개수에서 역산)
- 서술·논술 비율

숫자를 AI에게 맡기면 결과가 검증에 걸리고, 교사는 결국 심화 화면으로 들어가야 한다.
그러면 간단 버전을 쓴 의미가 없다. **간단 버전의 결과는 검증을 처음부터 통과한
상태로 나와야 한다.**

간단 버전에서 교사가 주는 것은 여섯 가지다 — 과목명, 학년, 지도교사, 정기시험 앵커,
수행평가 실시 주차·명칭, **실시 의도(줄글)**. 의도가 AI의 주 재료이므로
입력란을 크게 두고 길게 쓰도록 유도한다.

## 개발 순서

**심화 버전이 먼저다.** 데이터 모델·검증·hwpx 렌더링이 전부 여기서 나온다.
간단 버전은 그 위에 입력 화면 하나와 AI 프롬프트 세트만 얹으면 된다.

1. 데이터 모델 + Prisma 스키마
2. 성취기준 xlsx 임포트 스크립트
3. **hwpx 렌더러 + 왕복 테스트** — 가장 먼저 검증할 것. 여기서 막히면 나머지가 무의미하다
4. 검증 엔진 (로직 15개)
5. 심화 입력 화면 (기본 정보 → 진도 설계 → 수행평가 → 루브릭)
6. 검토 화면
7. 간단 입력 + OpenRouter 연동
8. 담당자 세팅 화면

3번을 3일차 안에 끝내지 못하면 나머지 일정을 다시 짜야 한다.

## 테스트

각 단계마다 **실제 hwpx를 열어 확인**한다. zip 무결성과 XML 파싱만으로는 부족하다.
